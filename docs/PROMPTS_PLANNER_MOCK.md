# Планировщик целей — промпты на mock

Канон поведения: [tz-planner-agent.md](tz-planner-agent.md). Циферблат: [TZ.md](TZ.md). Эти промпты не поднимают сервер.

Один промпт — один чат. Вставляйте блок **Prompt** целиком. **Зачем** в агент не копируйте. Следующий промпт начинайте, когда Acceptance предыдущего уже в репозитории.

Что получится на телефоне: лист «Спланировать цель», три вердикта, согласие пишет сектора, на «Отчётах» две кнопки сбора и заметка в существующем списке. Сеть не вызывается. Отказ сервиса включается целью, которая начинается со слова `офлайн`.

Что эти промпты не делают: модуль `server/`, Ktor, Koog, Postgres, HTTP, вход по почте, чужие календари, сбор отчёта по расписанию, миграции Room.

Mock не выдумывает минуты наугад. Оценки шагов — фиксированная таблица. Свободные окна и вердикт считает чистая функция по правилам ТЗ, на телефоне. Текст «почему срок такой» и абзац отчёта — шаблон, числа в него подставляются из этой функции.

## 1. Ёмкость и mock-клиент

### Prompt

```
Роль: старший Android-разработчик (Kotlin 2, Compose, MVI, Koin). Правишь репозиторий ClockPlanner, пакет com.example.clockplannerproject, один модуль :app. Не создавай новый проект и не добавляй Gradle-модуль.

Контекст:
- Канон циферблата уже собран. Задачи, отрезки, повтор и заметки живут в kit.core (Task, TimeBlock, Importance, RecurrenceRule, TaskReport) и Room. TimeMath лежит в kit.core.time.
- Поставка планировщика описана в docs/tz-planner-agent.md. Сервер в этой поставке не пишем: ни server/, ни Ktor, ни Koog, ни Postgres, ни HTTP-клиент, ни базовый URL.
- Вместо POST /v1/plans и POST /v1/reports — интерфейс PlannerSource в :app и единственная реализация MockPlannerSource. Koin отдаёт только её.

Цель:
1. Модели запроса и ответа с полями из ТЗ: goal, deadline, zone, workStartMinute, workEndMinute (по умолчанию 540 и 1140), срез tasks. Ответ плана: draftId, verdict со значениями FITS, TIGHT, IMPOSSIBLE, freeMinutes, usableMinutes, requiredMinutes, steps, narrative. Шаг: title, date, startMinute, endMinute либо unplaced, estimateMinutes, bufferedMinutes = ceil(estimate * 1.2), importance, project.
2. Чистая функция ёмкости без UI и без mock-текста. Занятость даты: закрытые блоки экземпляра этой даты плюс блоки шаблона, у которого recurrence.occursOn(date), если экземпляра серии на эту дату нет. Открытый блок занимает только сегодня, от startMinute до текущей минуты. Ночной блок (end < start) режется по полуночи. Свободное окно = рабочий полуинтервал минус объединение занятости. usableMinutes = сумма floor(free * 4 / 5). Укладка жадная: самый длинный шаг в самое раннее цельное окно, шаг не дробится, существующие блоки не двигаются. FITS — все легли и requiredMinutes <= usableMinutes, длина куска = bufferedMinutes. TIGHT — все легли и usableMinutes < requiredMinutes <= freeMinutes, длина куска = estimateMinutes. IMPOSSIBLE — суммы не хватает или хотя бы один шаг без цельного окна; у него unplaced = true.
3. MockPlannerSource. Оценки не из модели, а из таблицы:
   - цель начинается с «офлайн» (без учёта регистра) — отказ «сервис недоступен», черновика нет, задачи не читаются на запись;
   - цель содержит «десятки» — четыре шага по 600 минут, проект = название цели;
   - иначе три шага 120, 150 и 120 минут с названиями «{цель}: собрать», «{цель}: черновик», «{цель}: вычитка», проект = название цели, importance MEDIUM.
   Narrative — короткая русская фраза по вердикту. Для IMPOSSIBLE в тексте есть нехватка минут (required − free, не меньше 0) и три выхода: укоротить цель, сдвинуть день, снять необязательное. Числа только из функции ёмкости.
4. Повтор того же канонического запроса (цель, срок, окно, хеш среза) возвращает тот же draftId и тот же черновик из памяти процесса. Пустая цель, срок раньше локального сегодня, окно нулевой длины или start >= end — отказ до укладки, без черновика.
5. DataStore: при первом вызове plan или report создать UUID устройства и хранить его. Mock может читать ключ и не отправлять его наружу. Принятые планы в этом промпте только модель и хранилище, без экрана.
6. Юнит-тесты ёмкости: встреча 10:00–12:00 не двигается; открытый таймер не занимает завтра; повтор правила Daily занимает будущий день, если экземпляра серии нет; FITS при коротких шагах и окне 9:00–19:00; TIGHT, когда required между usable и free; IMPOSSIBLE, когда нет цельного окна или сумма больше free. Отдельный тест mock: «офлайн …» не возвращает шаги; два одинаковых запроса — один draftId.

Non-goals: лист «Спланировать цель», кнопки на «Отчётах», запись Task через репозиторий, смена схемы Room, Hilt, KMP, сеть.

Ограничения:
- Код, KDoc, комментарии — английский. Строки, которые увидит пользователь, — в values и values-ru, даже если экран ещё впереди.
- kotlinx-datetime в kit.core. java.time туда не импортировать.
- kit.render не трогать.

Acceptance:
- ./gradlew :app:testDebugUnitTest для новых тестов зелёный.
- В репозитории нет зависимости Ktor и нет каталога server/.
- Поиск по проекту не находит вызовов HttpURLConnection, OkHttp, Ktor для планировщика.

Output: список файлов, как прогнать тесты, что специально не сделано.
```

### Зачем

Вердикт и укладка должны совпасть со сценарием ТЗ. Mock подменяет только «модель» и транспорт. Иначе встреча 10:00–12:00 и «Не помещается» превращаются в зашитый JSON.

## 2. Лист цели и согласие

### Prompt

```
Роль: старший Android-разработчик Compose / MVI. Правишь :app в ClockPlanner. Сервер не добавляй. Источник черновика — уже существующий MockPlannerSource / PlannerSource. Если его ещё нет, остановись и скажи, что сначала нужен промпт 1.

Контекст:
- Экран задач: ui/task/TasksScreen.kt и TasksViewModel. Экран дня читает те же Task через TaskRepository. Цвета секторов — TaskPalette.
- Макет листа: stitch_timedial_planner_ui_kit, экраны plan_sheet_* и tasks_plan_entry. Бумага и терракота уже в ui/theme. Не копируй HTML в Compose.
- Пока согласия нет, уход с листа ничего не пишет. Повтор того же запроса показывает тот же черновик (это уже делает mock).

Цель:
1. На экране задач действие «Спланировать цель». Лист: текст цели, день срока (не раньше сегодня), рабочее окно по умолчанию 09:00–19:00. Окно сужается и сдвигается только внутри этих суток. Ночное окно через полночь задать нельзя: такая правка объясняется на форме и запрос не уходит.
2. Пока mock считает, кнопка «Поставить на циферблат» недоступна. Циферблат и список задач не меняются.
3. Ответ показывает один вердикт: «Помещается», «Впритык» или «Не помещается», три числа (свободно, с запасом, нужно) и narrative. Шаги: название, день, отрезок или пометка «неразмещён», проект.
4. До согласия шаг можно убрать. Пересчёт минут — на телефоне по уже полученным estimateMinutes и bufferedMinutes, без нового вызова PlannerSource, если оценки оставшихся шагов те же. Вердикт после удаления пересчитывается теми же правилами FITS / TIGHT / IMPOSSIBLE. Неразмещённый шаг остаётся в списке.
5. Перенос шага на другой день внутри срока — правка черновика. Если в этот день нет цельного окна нужной длины, шаг становится unplaced. Новый вызов mock не нужен.
6. Смена срока или окна снова вызывает PlannerSource. Пустая цель, вчерашний срок и окно нулевой длины оставляют форму с объяснением, черновик не открывается.
7. Цель с префиксом «офлайн» показывает сообщение, что сервис недоступен, форма остаётся, уже стоящие задачи не меняются. Повтор безопасен.
8. «Поставить на циферблат» доступна при любом вердикте. При IMPOSSIBLE на циферблат попадают только шаги с цельным окном. Остальные остаются в листе и в задачи не пишутся.
9. Согласие создаёт обычные Task через TaskRepository.upsert: один закрытый TimeBlock, status TODO, project как в шаге, date шага, цвет из TaskPalette (следующий цвет палитры, не цвет из ответа — его нет). Существующие задачи и их отрезки не сдвигаются. Принятый план (название цели, срок, шаги, которые реально записаны) кладётся в DataStore. Схему Room не повышать.
10. @Preview листа для пустой формы, FITS и IMPOSSIBLE с одним неразмещённым шагом.

Non-goals: кнопки «Собрать за сегодня» и «Собрать за неделю», сеть, Hilt, Migration, правка kit.render, материализация повторов на весь горизонт (видимый день по-прежнему делает RecurrenceMaterializer).

Ограничения:
- MVI: UiState, UiIntent, UiEffect. Тяжёлую укладку не считать внутри draw().
- Строки UI в values и values-ru. Код и KDoc на английском.
- Закрытый прошедший блок не предлагать к правке и не двигать при записи новых задач.

Acceptance:
- Сценарий без эмулятора, юнит-тестом ViewModel или чистой функции: сегодня занято 10:00–12:00, цель «Подготовить отчёт», срок через два дня, окно 9:00–19:00. До согласия репозиторий не получает новые задачи. После согласия встреча на месте, новые задачи лежат в свободных минутах, статус TODO.
- Цель «десятки часов», срок завтра, окно почти занято встречей: вердикт IMPOSSIBLE. Согласие пишет только размещённые шаги.
- Срок вчера: эффекта записи нет, состояние остаётся формой с текстом, что день уже прошёл.
- ./gradlew :app:testDebugUnitTest зелёный для новых тестов.

Output: список файлов, что нажать в приложении, что специально не сделано.
```

### Зачем

Согласие — единственная запись на циферблат. Отдельный промпт не даёт mock-у сразу писать Task «для удобства».

## 3. Отчёты из mock

### Prompt

```
Роль: старший Android-разработчик Compose / MVI. Правишь :app. HTTP не добавляй. Текст отчёта строит MockPlannerSource из среза, который телефон и так хранит локально.

Контекст:
- Экран ui/stats/ReportsScreen.kt уже показывает заметки TaskReport и умеет править и удалять их. Заметка без taskId не создаётся.
- Принятые планы лежат в DataStore после промпта 2. Если хранилища ещё нет, остановись.
- Подпись, что заметки живут на устройстве, остаётся. Mock ничего не отправляет и ничего не хранит как дневник.

Цель:
1. Две кнопки: «Собрать за сегодня» и «Собрать за неделю». Неделя — семь местных дней, включая сегодня. Сбора по расписанию нет.
2. Mock считает doneMinutes как сумму длительностей закрытых блоков за период. Выполненная задача без блоков даёт 0 минут и попадает в текст только названием. plannedMinutes — сумма длительностей шагов принятых планов, чьи дни попали в период. Пустой период — успешный ответ: в тексте прямо сказано, что закрытых отрезков нет.
3. Если за эти дни есть принятый план, абзац сравнивает, что стояло в плане и что закрыто. Если принятого плана нет, абзац прямо говорит, что сравнивать не с чем. Это шаблон со числами из сводки, не модель.
4. После ответа клиент пишет заметку через ReportRepository.upsert. Если у принятого плана есть безвременная задача с названием цели, заметка вешается на неё. Иначе клиент создаёт одну безвременную задачу «Отчёт yyyy-mm-dd» и вешает заметку на неё. Экран по-прежнему не создаёт заметку без taskId.
5. Готовую заметку можно поправить и удалить тем же UI, что и любую другую. Повтор кнопки создаёт новую заметку, старые не затирает.
6. Отказ mock (тот же путь, что «сервис недоступен») оставляет список заметок как был и показывает сообщение. Задачи не удаляются.
7. Юнит-тест: закрытый блок 2 часа и принятый шаг на сегодня дают сравнение в тексте; день без блоков и без плана даёт честный пустой текст и заметку; doneMinutes не считает открытый таймер будущим днём.

Non-goals: сервер, вложения, экспорт, смена схемы Room, правка циферблата, Hilt.

Ограничения:
- Строки в values и values-ru. Код на английском.
- MVI экрана отчётов сохрани. Новые намерения добавь к существующему контракту, не заводи второй ViewModel ради двух кнопок, если текущий уже владеет списком заметок.

Acceptance:
- ./gradlew :app:testDebugUnitTest для новых тестов зелёный.
- В списке отчётов после сбора видна заметка, её текст редактируется и удаляется.
- Подпись про хранение на устройстве на месте.

Output: список файлов, шаги на устройстве, что специально не сделано.
```

### Зачем

Отчёт в ТЗ — текст по локальному срезу. Mock собирает абзац на телефоне, заметка остаётся в Room, как и раньше.

## 4. Сценарий проверки целиком

### Prompt

```
Роль: старший Android-разработчик. Закрой дыры между листом цели, mock и отчётами. Новых сервисов не добавляй.

Контекст:
- Промпты 1–3 уже в репозитории: Capacity, MockPlannerSource, лист «Спланировать цель», кнопки сбора на «Отчётах». Если какого-то куска нет, не выдумывай сервер — допиши недостающий кусок mock-ом.
- Проверка из docs/tz-planner-agent.md, раздел «Как проверить». Сеть не выключаем: отказ сервиса — цель с префиксом «офлайн».

Цель:
Пройти сценарий и починить только то, что ему мешает.
1. На сегодня есть задача 10:00–12:00. «Спланировать цель», текст «Подготовить отчёт», срок пятница, окно 09:00–19:00.
2. Вердикт приходит, встреча на месте, новых секторов нет, кнопка постановки во время ожидания была недоступна.
3. «Поставить на циферблат» ставит шаги в свободные окна. Встреча не сдвинута. Статус новых задач — к выполнению. Цвет из палитры приложения.
4. Один новый шаг можно закрыть отрезком и отметить выполненным существующими действиями задачи. Планировщик не добавляет второй таймер.
5. «Собрать за сегодня» добавляет заметку про этот шаг. Текст заметки меняется и удаляется.
6. Цель «офлайн Подготовить отчёт» оставляет форму с сообщением, список задач тот же.
7. Срок вчера не открывает черновик и объясняет, что день уже прошёл.
8. Цель со словом «десятки» на завтра при занятом окне даёт «Не помещается». Без согласия новых секторов нет. С согласием на циферблат попадают только шаги с цельным окном.
9. Удаление шага в черновике не вызывает PlannerSource второй раз. Смена окна вызывает и получает новый draftId, если окно реально другое.

Non-goals: настоящий HTTP, модуль server/, расписание сбора, семейный план, почта, Room Migration, рефакторинг циферблата.

Ограничения:
- Не ослабляй тесты ёмкости, чтобы сценарий «прошёл» на константе.
- Не записывай задачи до нажатия «Поставить на циферблат».

Acceptance:
- Юнит-тесты покрывают пункты 2, 3, 6, 7, 8 и 9 без эмулятора.
- ./gradlew :app:testDebugUnitTest зелёный.
- Кратко напиши, какой пункт проверяется только глазами на устройстве (закрытие шага таймером и правка заметки, если это уже есть в UI и тестом ViewModel не дублируется).

Output: что было сломано, какие тесты добавлены, что осталось за пределами mock.
```

### Зачем

Четвёртый промпт не добавляет функций. Он заставляет агента сверить четыре куска с одним сценарием ТЗ и не подменить вердикт заготовленной строкой.
