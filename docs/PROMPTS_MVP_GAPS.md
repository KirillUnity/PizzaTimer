# Дыры MVP — отдельные промпты

Канон циферблата: [TZ.md](TZ.md). Поток: [STITCH_FLOW_PROMPT.md](STITCH_FLOW_PROMPT.md). Практика: [STITCH_LEARNING_PROMPT.md](STITCH_LEARNING_PROMPT.md). Планировщик на телефоне уже mock: [tz-planner-agent.md](tz-planner-agent.md), [PROMPTS_PLANNER_MOCK.md](PROMPTS_PLANNER_MOCK.md).

Один промпт — один чат. В агент вставляйте только блок **Prompt**. **Зачем** не копируйте. Следующий чат начинайте, когда Acceptance предыдущего уже в репозитории.

Порядок: **1 → 2 → 3 → 4** можно по очереди без ожидания друг друга, кроме практики: промпт **6** после **1**. Промпт **5** и промпт **7** сами по себе.

Что получится на телефоне:

- Строка «где остановился» и настроение остаются после перезапуска и привязаны к задаче. Карточка «День закрыт» в тот же местный день открывается снова. День при этом не замирает, заметка в «Отчётах» сама не появляется.
- Если на экране открыт сегодняшний день, в полночь экран переходит на новые сутки. День, выбранный стрелками или календарём, остаётся выбранным.
- Пример дня в debug появляется один раз на установку. Удалённый сегодня день остаётся пустым.
- Сообщения об ошибке дня, задач и отчётов идут на языке системы.
- В настройках можно выбрать фото под круг. Файл лежит в каталоге приложения.
- «Практика» открывается из «Настроек». Пять приёмов отмечаются по живым действиям. Пятой вкладки нет.
- Лист «Спланировать цель» прямо говорит, что расчёт идёт на этом телефоне. Режим полёта лист не ломает. Слова «офлайн» и «десятки» остаются тестовыми переключателями mock.

Что эти промпты не делают: модуль `server/`, Ktor, календарь Google или Apple, облако, виджеты, KMP, загрузку в Play, смену `applicationId`, класс Room `Migration`.

## 1. Фиксация паузы и закрытие дня

### Prompt

```
Роль: старший Android-разработчик (Kotlin 2, Compose, MVI, Koin). Правишь репозиторий ClockPlanner, пакет com.example.clockplannerproject, один модуль :app. Не создавай новый проект и не добавляй Gradle-модуль.

Контекст:
- Листок паузы, чип «Продолжить с» и карточка «День закрыт» уже на экране дня: ui/day/flow, DayUiState.pauseDraft / pauseMood / resumeCheckpoint / showDayClose. Пауза уже закрывает TimeBlock через TaskTimer.pause. Прошедший блок не переписывается.
- Текст фиксации, настроение и флаг «день закрыт» живут только в памяти ViewModel. Смена дня, смерть процесса и новый запуск их стирают. Настроение после «Зафиксировать» никуда не пишется.
- Принятый план и внешний вид уже лежат в DataStore. Схему Room не повышай: новая колонка задачи сотрёт локальную базу из-за fallbackToDestructiveMigration().

Цель:
1. После «Зафиксировать» сохрани для этой задачи текст (обрезанный, не пустой пробелами) и выбранное настроение Calm / Deep / Stuck. Хранилище — DataStore, не Room. Ключ — id задачи. Пустой текст не затирает уже сохранённую строку: остаётся прежняя фиксация, если она была.
2. «Пропустить» закрывает листок и не меняет сохранённую фиксацию.
3. Чип «Продолжить с: …» читается из хранилища, когда выбран этот сектор и нет открытого захода. Настроение видно на чипе теми же словами, что на листке: Спокойно, Глубоко, Застрял. Перезапуск процесса и возврат на этот день показывают тот же чип.
4. «Старт» снимает чип и удаляет сохранённую фиксацию этой задачи. Новый отрезок по-прежнему только добавляется. Закрытый блок не меняется.
5. Смена видимого дня прячет листок и карточку, но не удаляет фиксации задач.
6. «День закрыт» запоминается для местной даты, которую пользователь закрыл. Повторный вход в тот же местный день снова показывает карточку, пока её не скрыли. Следующие местные сутки карточку сами не показывают. Скрытие запоминается до следующего явного закрытия этого дня.
7. Карточка не запрещает Старт, правку и новые задачи. Она не создаёт TaskReport. Кнопка «В отчёты» по-прежнему только открывает вкладку отчётов. Если закрытых минут нет, текст карточки остаётся спокойным «Закрытых отрезков нет».
8. Юнит-тест без эмулятора: зафиксировать текст и настроение, создать новый ViewModel на тех же данных — чип на месте; Старт запись стирает; Пропустить чужую запись не трогает; закрытие даты D видно при входе на D и не видно на D+1.

Non-goals: пятая вкладка, практика, фото-фон, сеть, уведомления, класс Migration, правка углов в UI, блокировка дня, автосоздание заметки отчёта.

Ограничения:
- Код, KDoc, комментарии — английский. Строки, которые видит пользователь, — в values и values-ru.
- MVI дня сохрани. Тяжёлое не считай внутри draw().
- kit.render не импортирует DataStore.

Acceptance:
- ./gradlew :app:testDebugUnitTest для новых тестов зелёный.
- На устройстве: Пауза → строка и настроение → Зафиксировать → убить процесс → чип на секторе тот же. Старт чип убирает. Закрытый отрезок на циферблате тот же, что до Паузы.

Output: список файлов, что нажать, что специально не сделано.
```

### Зачем

Иначе тестер после перезапуска решит, что Пауза потеряла место остановки. Фиксация — свойство задачи, не кадра экрана. Закрытие дня — пометка даты, не замок и не отчёт.

## 2. Полночь на открытом «сегодня»

### Prompt

```
Роль: старший Android-разработчик Compose / MVI. Правишь :app. Сервер и уведомления не добавляй.

Контекст:
- DayViewModel держит selectedDate. Сейчас он ставится один раз из timeProvider.today() и дальше меняется только стрелками и календарём. Часы в отверстии идут каждую секунду, календарный день экрана при переходе через полночь остаётся вчерашним, если пользователь смотрел «сегодня».
- Повтор на видимый день уже делает RecurrenceMaterializer. Его горизонт не расширяй.

Цель:
1. Пока видимая дата совпадает с местным «сегодня», смена местных суток (now перешёл на следующий LocalDate) сама открывает новый день: задачи, повтор на этот день, половина AM/PM по новому времени. Пример дня заново не подкладывай.
2. Если пользователь ушёл стрелкой или календарём на другую дату, полночь эту дату не подменяет. Возврат на «сегодня» снова следует за часами.
3. Открытый таймер, который шёл через полночь, не переписывай задним числом в этом промпте: закрой его существующей Паузой на минуте до полуночи только если это уже делает TaskTimer. Если нет — оставь блок как есть и опиши это в Output. Новые минуты после полуночи не дописывай в вчерашний блок.
4. Юнит-тест: выбранное «сегодня» 23:59, следующий тик — следующий LocalDate, selectedDate равен новому дню. Выбранное «вчера» при том же тике не меняется.

Non-goals: push-уведомление в полночь, виджет, сдвиг чужих задач, Room Migration, автопауза, если её ещё нет в TaskTimer.

Ограничения:
- Дата в домене — kotlinx-datetime. В kit.core не импортируй java.time.
- Строки не хардкодь в Composable.

Acceptance:
- Новый тест зелёный в :app:testDebugUnitTest.
- На устройстве или в тесте ViewModel видно два исхода: следование за сегодня и удержание чужого дня.

Output: список файлов, как проверить полночь без ожидания реальных суток, что специально не сделано.
```

### Зачем

Ночной прогон не должен оставлять человека на вчерашнем круге, пока он не уходил с «сегодня». Чужой день, открытый нарочно, полночь не отбирает.

## 3. Пример дня один раз

### Prompt

```
Роль: старший Android-разработчик. Правишь :app. Релизный seeder не включай.

Контекст:
- SampleDaySeeder.seedIfEmpty в debug, если на местное сегодня в Room пусто, снова вставляет SampleTasks.typicalDay. Вызов из DayViewModel при загрузке дня. Поэтому удаление всех задач сегодня возвращает пример. Пустой день и путь «добавить задачу» на debug так не увидеть.
- В release seeder уже ничего не пишет. Это сохрани.

Цель:
1. Флаг в DataStore: пример на эту установку уже вставляли. Пока флаг ложь и база задач пуста целиком (не только сегодня), debug один раз вставляет typicalDay на местное сегодня и поднимает флаг.
2. Пустое «сегодня» после этого флага остаётся пустым: ни смена дня, ни перезапуск, ни удаление последней задачи пример не возвращают.
3. Если в базе уже есть любая задача, флаг тоже подними и ничего не вставляй.
4. Онбординг и пустое состояние дня не ломай: на пустом дне по-прежнему есть действие добавить задачу.
5. Юнит-тест seeder с поддельным репозиторием и флагом: первый пустой вызов пишет пример и флаг; второй пустой вызов не пишет; непустая база не пишет.

Non-goals: кнопка «загрузить демо» в настройках, другой набор примеров, seed в release, Room Migration, удаление SampleTasks из Preview.

Ограничения:
- Не повышай версию Room ради флага.
- Код на английском. Новых пользовательских строк нет, если не понадобилась подпись. Если понадобилась — values и values-ru.

Acceptance:
- Новый тест зелёный.
- Сценарий: поставить debug, увидеть пример, удалить задачи сегодня, перезапустить — день пустой, пример не вернулся.

Output: список файлов, как сбросить флаг (очистка данных приложения), что специально не сделано.
```

### Зачем

Тестеру нужен пустой день без переустановки. Пример полезен на первом запуске и мешает, когда его возвращают после удаления.

## 4. Сообщения об ошибках на языке системы

### Prompt

```
Роль: старший Android-разработчик Compose. Правишь :app. Новых экранов нет.

Контекст:
- Снэкбары дня, задач и отчётов часто показывают зашитый английский: «Could not load the day», «Could not save task», «Could not place the plan», «Could not collect the report» и соседние fallback в DayViewModel, TasksViewModel, ReportsViewModel. Экран уже умеет брать строки из resources. Язык UI — язык системы, values и values-ru.
- ViewModel не должен держать Android Context ради одной строки. Сейчас эффект несёт готовый String.

Цель:
1. Запасной текст снэкбара — строка из resources, русская и английская. Эффект несёт id строки или маленький набор причин, а экран резолвит её через stringResource. Exception.message в снэкбар не подставляй: платформенный текст часто английский. Его можно оставить в логе.
2. Покрой запасные тексты дня (загрузка, пример, размер, обновление, копия, перенос, таймер, удаление), задач (заметка, загрузка, сохранение, удаление, копия, перенос, на диаграмму, постановка плана) и отчётов (сбор, сохранение заметки).
3. Уже локализованные отказы планировщика (пустая цель, вчера, окно, «сервис недоступен») не заменяй английским fallback.
4. Юнит-тест: намерение, которое заканчивается ошибкой репозитория, кладёт в эффект причину-ресурс, а не английское предложение.

Non-goals: перевод KDoc, перевод логов, внутриприложенческий переключатель языка, новые ошибки валидации, правка циферблата.

Ограничения:
- Существующие контракты эффектов можно сузить, если экраны дня, задач и отчётов обновлены вместе. Второй канал сообщений не заводи.
- Preview, где показан снэкбар, использует ресурс, не литерал.

Acceptance:
- ./gradlew :app:testDebugUnitTest зелёный.
- Поиск по main больше не находит эти английские fallback в ViewModel. Строки есть в values и values-ru.

Output: список новых string name, какие эффекты сменили тип, что специально не сделано.
```

### Зачем

Тестер с русским языком системы не должен читать «Could not load the day», когда остальной интерфейс уже русский.

## 5. Фото под круг

### Prompt

```
Роль: старший Android-разработчик. Правишь :app. Облако и широкое разрешение хранилища не добавляй.

Контекст:
- BackgroundConfig.UserImage уже есть в модели и в DataStore внешнего вида. Экран настроек и DialUnderlay показывают заглушку «фон из фото появится позже» и фото не рисуют. Пресеты пергамент, ночные чернила и терракота уже рисуются под DIAL и PIZZA со скримом, подписи остаются читаемыми.
- Вложения отчётов уже копируются в filesDir через системный выбор файла, без READ_EXTERNAL_STORAGE. Повтори этот приём, каталог другой: не report-media.

Цель:
1. В настройках выбор «Своё фото» открывает системный выбор изображения. Выбранный файл копируется в filesDir приложения. В Appearance сохраняется путь этой копии, не чужой content://, который протухнет.
2. Под DIAL и PIZZA рисуется это изображение на всю подложку, сверху тот же бумажный скрим, что у пресетов, чтобы подписи сектора читались. PETALS и LIST подложку фото не обещают, если пресеты там тоже не рисуются: сделай так же, как пресет.
3. Повторный выбор заменяет файл. Сброс на «Нет» или пресет оставляет круг без фото и удаляет копию из filesDir. Битый или пропавший файл не роняет экран: подложка как None и короткая локализованная оговорка в настройках.
4. Строку background_user_coming на выбранном фото больше не показывай.
5. Юнит-тест копирования пути: после выбора в репозитории вида лежит путь внутри каталога приложения; сброс очищает UserImage.

Non-goals: кадрирование, фильтры, несколько фото, видео, фон из галереи по широкому permission, облако, Room Migration, пиксель-перфект к Stitch.

Ограничения:
- Манифест без READ_MEDIA_IMAGES и READ_EXTERNAL_STORAGE, если хватает Photo Picker или GetContent.
- Код на английском. Новые подписи в values и values-ru.
- Битокарту не декодируй заново внутри draw() на каждый кадр. Помни изображение в стороне от цикла рисования.

Acceptance:
- Новый тест зелёный.
- На устройстве: выбрать фото, увидеть его под циферблатом, перезапустить — фото на месте, подписи читаются. «Нет» возвращает бумагу без фото.

Output: список файлов, какое разрешение не добавлено, что специально не сделано.
```

### Зачем

Пункт в настройках уже нажимается и обещает фото. Пока вместо фото текст «появится позже», это дыра приёмки, а не будущий режим.

## 6. Практика

### Prompt

```
Роль: старший Android-разработчик Compose / MVI. Правишь :app. Пятую вкладку и очки не добавляй. Если промпт 1 ещё не в репозитории (фиксация и закрытие дня не сохраняются), остановись и напиши, что сначала нужен промпт 1.

Контекст:
- Введение из нескольких страниц уже есть. Настройки умеют показать его снова. Отдельного входа «Практика» нет. README описывает экраны практики как ещё не собранные.
- Канон экранов: docs/STITCH_LEARNING_PROMPT.md. Это приёмы живого дня, не курс и не викторина. HTML и Tailwind из stitch_timedial_planner_ui_kit в Compose не копируй. Бери иерархию и тексты, рисуй на токенах ui/theme.
- Нижняя навигация: День, Задачи, Отчёты, Настройки. Пока практика открыта, активна Настройки.

Цель:
1. В настройках строка «Практика». Экран хаба: заголовок «Практика», строка «ОПРОБОВАНО · N из 5», тонкая полоска, пять строк. Неделя: семь столбцов закрытых минут, понедельник–воскресенье, пустой день остаётся в ряду без красного. Ссылка «Показать введение» открывает уже существующий онбординг.
2. Пять приёмов и как они становятся «опробовано», флагами в DataStore, по живому действию, без квиза:
   - «День — циферблат» — пользователь выбрал сектор на DIAL.
   - «Доли leftover 5:3:2» — сохранил задачу без отрезков времени.
   - «Старт в центре» — успешный Старт.
   - «Фиксация потока» — «Зафиксировать» с непустым текстом.
   - «Закрытие дня» — пользователь закрыл день карточкой.
   Снятие флага в этом промпте нет. Повтор действия остаётся «опробовано».
3. Урок каждого приёма: короткий текст из канона Stitch, миниатюра или схема без второго живого циферблата, основная кнопка ведёт на вкладку День. Урок leftover объясняет 5:3:2 словами и тремя долями, не новым расчётом углов в UI.
4. Неделя считает закрытые минуты местных семи дней, включая сегодня, из уже сохранённых блоков. Открытый таймер в сумму не входит. Пустая неделя говорит «Закрытых отрезков нет» спокойно.
5. Хаб при нуле из пяти показывает те же пять строк «ещё нет» и ведёт к дню. Серий, XP, конфетти и пятой вкладки нет.
6. @Preview хаба 0 из 5 и 3 из 5. Юнит-тест: три флага дают «3 из 5»; закрытый блок 65 минут попадает в столбец своего дня; открытый блок не попадает.

Non-goals: сервер, уведомления, виджет, геймификация, пятый пункт nav, копирование HTML, новый DialRenderer, Room Migration, пиксель-перфект.

Ограничения:
- MVI отдельного экрана или ясное состояние внутри настроек. День не переписывай ради урока.
- Строки в values и values-ru. Код на английском.
- Доли 5:3:2 на уроке не считай заново: это пояснение уже существующего layout.

Acceptance:
- Новые тесты зелёные.
- На устройстве: Настройки → Практика → урок → День. После Старта хаб показывает этот приём опробованным и после перезапуска тоже. Вкладка Настройки остаётся выбранной, когда практика открыта поверх.

Output: список файлов, какие действия ставят какие флаги, что специально не сделано.
```

### Зачем

Кадры практики уже в README, в сборке входа нет. Приём считается сделанным только если человек сделал его на настоящем дне.

## 7. Честный mock планировщика

### Prompt

```
Роль: старший Android-разработчик. Правишь :app. HTTP, Ktor и каталог server/ не добавляй.

Контекст:
- «Спланировать цель» и сбор отчётов уже ходят в MockPlannerSource. Расчёт на телефоне. Отказ «сервис недоступен» включается целью, которая начинается со слова «офлайн». Четыре длинных шага включаются словом «десятки». Сеть при этом не вызывается: режим полёта лист не меняет.
- Тестер, который выключит сеть, решит, что планировщик сломан, либо решит, что отказ сети проверен. Это дыра приёмки, не дыра транспорта.

Цель:
1. На форме цели, до запроса и на черновике, одна спокойная строка: расчёт идёт на этом телефоне, сеть не нужна. Режим полёта не показывает «сервис недоступен».
2. Слова «офлайн» и «десятки» оставь как есть в MockPlannerSource. Рядом с полем цели короткая подсказка для проверки, видимая в debug-сборке и скрытая в release: цель с «офлайн» в начале — отказ, цель со словом «десятки» — заведомо тяжёлые шаги. В release этих слов в интерфейсе нет, но mock на них по-прежнему отвечает так же, если их ввести.
3. Существующие тесты Capacity и MockPlannerSource не ослабляй и не переименовывай вердикты.
4. Юнит-тест не нужен на саму строку, если она из resources. Добавь тест только если прячешь подсказку флагом сборки и этот флаг легко подменить.

Non-goals: реальный POST /v1/plans, обработка отсутствия сети, почта, семейный план, смена схемы Room, другой текст вердиктов FITS / TIGHT / IMPOSSIBLE.

Ограничения:
- Строки в values и values-ru.
- Не логируй срез задач наружу.

Acceptance:
- :app:testDebugUnitTest зелёный, старые тесты mock на месте.
- На форме видно, что расчёт местный. Самолётный режим оставляет ту же форму и тот же успешный черновик для обычной цели. «офлайн …» по-прежнему отказ.

Output: какие строки добавлены, что по-прежнему делает mock, что специально не сделано.
```

### Зачем

Дыра в том, что лист выглядит как сетевой сервис. Закрытие — сказать правду на форме. Настоящий сервер этим промптом не начинается.
